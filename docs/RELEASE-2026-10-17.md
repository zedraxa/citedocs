## 2. Veritabanı Migrasyonları (Database Migrations)

### 2.1 Yeni Eklenen Migrasyon
- **Dosya:** `apps/server/drizzle/0002_fuzzy_marvex.sql`
- **Etkilenen Tablo:** `pdf_annotations`
- **İçerik:**
  ```sql
  CREATE TABLE "pdf_annotations" (
    "id" uuid PRIMARY KEY DEFAULT gen_random_uuid() NOT NULL,
    "owner_user_id" uuid NOT NULL,
    "attachment_id" uuid NOT NULL,
    "zotero_key" text NOT NULL,
    "version" integer DEFAULT 0 NOT NULL,
    "parent_item_key" text,
    "annotation_type" text DEFAULT 'highlight' NOT NULL,
    "annotation_text" text DEFAULT '' NOT NULL,
    "annotation_comment" text DEFAULT '' NOT NULL,
    "annotation_color" text DEFAULT '#ffd400' NOT NULL,
    "annotation_page_label" text DEFAULT '1' NOT NULL,
    "annotation_sort_index" text DEFAULT '' NOT NULL,
    "annotation_position" jsonb,
    "image_path" text,
    "created_at" timestamp with time zone DEFAULT now() NOT NULL,
    "updated_at" timestamp with time zone DEFAULT now() NOT NULL
  );
  ALTER TABLE "pdf_annotations" ADD CONSTRAINT "pdf_annotations_owner_user_id_users_id_fk" FOREIGN KEY ("owner_user_id") REFERENCES "public"."users"("id") ON DELETE cascade ON UPDATE no action;
  ALTER TABLE "pdf_annotations" ADD CONSTRAINT "pdf_annotations_attachment_id_attachments_id_fk" FOREIGN KEY ("attachment_id") REFERENCES "public"."attachments"("id") ON DELETE cascade ON UPDATE no action;
  CREATE INDEX "pdf_annotations_owner_idx" ON "pdf_annotations" USING btree ("owner_user_id");
  CREATE INDEX "pdf_annotations_attachment_idx" ON "pdf_annotations" USING btree ("attachment_id");
  CREATE INDEX "pdf_annotations_owner_key_idx" ON "pdf_annotations" USING btree ("owner_user_id","zotero_key");
  ```
- **Çalıştırma Şekli:** Fastify backend servisi (`apps/server`) ayağa kalkarken `src/db/migrate.ts` aracılığıyla migrasyonları **otomatik olarak** idempotent biçimde uygular. İstenirse manuel olarak konteyner içinde `pnpm db:migrate` tetiklenebilir.
- **Geriye Dönük Uyumluluk:** Yeni tablo bağımsızdır, mevcut `users` veya `documents` verilerine zarar vermez.

## 3. Ortam Değişkenleri (Environment Variables) ve Varsayılanlar

Üretim sunucusundaki `/opt/citedocs/.env` dosyasında bulunması gereken yeni veya güncellenen parametreler:

| Değişken | Varsayılan / Örnek Değer | Açıklama |
|---|---|---|
| `S3_DOCUMENTS_BUCKET` | `citedocs-documents` | ONLYOFFICE tarafından kaydedilen `.docx` belgelerinin saklandığı kova adı. |
| `S3_ATTACHMENTS_BUCKET` | `citedocs-attachments` | Öğrenci referans PDF ve eklerinin saklandığı kova adı. |
| `S3_FORCE_PATH_STYLE` | `true` | MinIO ve yerel S3 uç noktaları için path-style erişimi etkinleştirir (AWS S3 için `false`). |
| `ONLYOFFICE_JWT_SECRET` | *(gizli anahtar)* | ONLYOFFICE Document Server ile backend arasındaki HS256 JWT doğrulama anahtarı. |
| `ONLYOFFICE_INTERNAL_URL` | `http://onlyoffice/oo` (veya `http://localhost/oo`) | Backend servisinin Document Server API'sine eriştiği dahili adres. |
| `ONLYOFFICE_PUBLIC_URL` | `/oo` | Tarayıcının Document Server JavaScript kütüphanelerine ulaştığı genel yol öneki. |
| `ONLYOFFICE_STORAGE_URL` | `http://server:3000` | Document Server'ın belge indirme ve kaydetme isteklerini ilettiği dahili CiteDocs adresi. |
| `BACKUP_DIR` | `/opt/citedocs/backups` | Yedek arşivlerinin (`.tar.gz`) saklanacağı dizin. |
| `MIN_FREE_DISK_MB` | `2048` | Yedekleme öncesi gereken asgari boş disk alanı eşiği (MB). |
| `DISK_RESERVE_PERCENT` | `20` | Yedekleme sonrasında diskte kalması gereken güvenlik rezervi yüzdesi (%). |
| `KEEP_LOCAL_AFTER_UPLOAD` | *(boş / isteğe bağlı: 1 veya 2)* | Uzak S3 yüklemesi aktifse yerelde saklanacak en yeni arşiv sayısı. |
| `BACKUP_S3_URI` | *(boş / isteğe bağlı)* | Felaket kurtarma için uzak S3 yedek kovası (örn: `s3://citedocs-backups-remote/`). |

## 4. Birimler (Volumes), Önbellek (Cache) Dizinleri ve Disk Etkisi

### 4.1 CSL Stil İndeksi Bellek Önbelleği (`StyleIndexService`)
- **Depolama Yeri:** %100 Bellek İçi (In-Memory).
- **Disk Etkisi:** **0 Bayt (Diske yazılmaz).**
- **RAM Etkisi:** Resmi Zotero deposundaki ~10.865 stil JSON nesnesi RAM'de yalnızca ~2-5 MB yer kaplar. 12 saatlik TTL ile güncellenir.
- **Güvenlik / Fallback:** İnternet erişimi kesilirse gömülü en popüler 10 stil (`FALLBACK_STYLES`) kesintisiz hizmet verir.

### 4.2 S3 / MinIO Depolama Kovaları
- **Kovalar:** `citedocs-documents` ve `citedocs-attachments`.
- **Otomatik Oluşturma:** Sunucu başlatılırken `ensureBucket()` fonksiyonu ile her iki kova yoksa otomatik ve idempotent biçimde oluşturulur.
- **Disk Büyümesi:** 20 öğrenci için başlangıçta ~1 GiB; tavan kota senaryosunda öğrenci başına 5 GB'a kadar ölçeklenir.

### 4.3 ONLYOFFICE Volume ve Önbellek Dizinleri
- **Kalıcı Volume'lar:**
  - `oo_data`: `/var/www/onlyoffice/Data` (özel sertifikalar ve yapılandırmalar).
  - `oo_logs`: `/var/log/onlyoffice` (servis logları).
- **Dahili Cache Dizini:** `/var/lib/onlyoffice/documentserver/App_Data/cache/files` (geçici düzenleme oturumları ve dönüştürme tamponları).
- **Disk İzleme Eşiği:** `docs/CAPACITY.md` uyarınca cache ve logların 5 GiB üzerinde uyarı, 10 GiB üzerinde kritik alarm vermesi hedeflenmiştir.

### 4.4 Yedekleme Arşivleri ve Staging Alanı
- **Konum:** `/opt/citedocs/backups`
- **Disk Güvenliği:** `citedocs-backup.sh` ön alan denetimi ile dosya sisteminde $S + A + \%20$ alan yoksa işlemi güvenle durdurur. Arşiv sıkıştırılır sıkıştırılmaz staging alanı derhal silinir. 7 günlük + 4 haftalık rotasyonla yerelde en fazla 11 arşiv saklanır.

## 6. Yeni Cron Görevleri ve Systemd Zamanlayıcıları

Üretim sunucusuna kurulabilecek 2 operasyonel zamanlayıcı mevcuttur:

### 6.1 Günlük Otomatik Yedekleme (Daily Backup)
- **Cron Örneği:** `deploy/backup/citedocs-backup.cron`
  - **Hedef Konum:** `/etc/cron.d/citedocs-backup`
  - **Zamanlama:** Her gün saat `03:30 Europe/Istanbul`
- **Systemd Alternatifi:** `deploy/backup/citedocs-backup.service` + `citedocs-backup.timer`
  - **Zamanlama:** `OnCalendar=*-*-* 03:30:00 Europe/Istanbul`

### 6.2 Periyodik Kapasite ve Disk Güvenlik Denetimi (Capacity Monitoring)
- **Systemd Tanımı:** `deploy/ops/citedocs-capacity.service` + `citedocs-capacity.timer`
- **Zamanlama:** Her 5 dakikada bir (`OnUnitActiveSec=5m`)
- **İşlev:** Disk doluluğu (%80 uyarı, %90 kritik), kullanılabilir RAM (<768 MB uyarı, <384 MB kritik), Swap kullanımı (%25 uyarı, %50 kritik) ve ONLYOFFICE cache boyutunu tarar; eşik aşımında log ve opsiyonel webhook basar.

## 7. Yeni ve Değişen HTTP API Rotaları

| Metot | Uç Nokta | Yetkilendirme | Açıklama |
|---|---|---|---|
| `POST` | `/api/documents/:id/convert-to-docx` | `requireAuth` | ODT belgelerini ONLYOFFICE `ConvertService.ashx` üzerinden DOCX kopyasına dönüştürür (ZC-01). |
| `GET` | `/api/styles` | Genel / Oturum | Zotero CSL stillerini arar ve listeler (`q`, `limit` parametreleri, ZC-03, ZC-05). |
| `GET` | `/api/styles/:id` | Genel / Oturum | Belirli bir CSL stilinin detay ve XML tanımını döner. |
| `PUT` | `/api/documents/:id/style` | `requireAuth` | Düzenlenen belgenin `.docx` arşivini açıp Zotero stil tercihlerini günceller ve oturum anahtarını tazeler. |
| `GET` | `/api/documents/:id/citations` | `requireAuth` | Hem Word `.docx` hem LibreOffice `.odt` dosyalarından atıf, kaynakça ve stil durumunu döner (ZC-02). |
| `POST` | `/api/onlyoffice/callback/:id` | JWT / İmzalı | `status: 6` force-save callback'lerinde oturum anahtarını korur, deduplikasyon uygular; `status: 2`/`status: 4` ile oturumu sonlandırır. |
| `POST` | `/api/documents` | `requireAuth` | Yeni oluşturulan belgelere varsayılan olarak "Adsız Belge" Türkçe başlığını verir (BUG-03). |

## 8. Geri Alma Adımları (Rollback Runbook)

Dağıtım sonrasında beklenmeyen bir regresyon veya sistem hatası meydana gelirse uygulanacak adımlar:

### Adım 8.1: Kod Seviyesinde Geri Alma
```bash
cd /opt/citedocs
# Bir önceki kararlı commit veya etikete dönün
git checkout 72fd910
```

### Adım 8.2: Konteynerlerin Yeniden Derlenmesi ve Başlatılması
```bash
sudo docker compose -f deploy/docker-compose.prod.onlyoffice.yml up -d --build
```

### Adım 8.3: Veritabanı Geri Alma (İsteğe Bağlı)
`0002_fuzzy_marvex.sql` migrasyonunu geri almak gerekirse:
```bash
# Sadece yeni eklenen pdf_annotations tablosunu kaldırmak için:
docker exec -i citedocs-postgres psql -U citedocs -d citedocs -c 'DROP TABLE IF EXISTS "pdf_annotations" CASCADE;'
```
Veya tam bir felaket anında son temiz yedekten geri yükleme yapmak için:
```bash
deploy/backup/citedocs-restore.sh /opt/citedocs/backups/citedocs-backup-<TARIH>.tar.gz --yes
```

### Adım 8.4: Zamanlayıcıların Kaldırılması
```bash
# Cron görevini devre dışı bırakmak için:
sudo rm -f /etc/cron.d/citedocs-backup

# Systemd zamanlayıcılarını durdurmak için:
sudo systemctl disable --now citedocs-backup.timer citedocs-capacity.timer
sudo systemctl daemon-reload
```
